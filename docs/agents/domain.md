# Domain documentation

This is a single-context repository: one root `GLOSSARY.md` and root `docs/adr/` directory.

Before exploring an area, read `GLOSSARY.md` and relevant ADRs if present. If `GLOSSARY-MAP.md` is introduced later, follow its links to relevant context glossaries. Proceed silently when these documents are absent; domain-modeling workflows create them when terms or decisions are resolved.

Use the glossary vocabulary consistently in issues, code discussions, tests and documentation. Reconsider invented synonyms. Flag proposals that contradict an existing ADR explicitly rather than silently overriding it.
